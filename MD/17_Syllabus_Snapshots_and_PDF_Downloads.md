# Syllabus Snapshots and HTML/PDF Downloads

Practical reference for how CSMS freezes syllabus versions, previews saved HTML, and generates downloadable PDF files.

## Purpose

When a faculty member creates a saved version, CSMS preserves an immutable HTML copy of the syllabus. Users can then:

- Open the saved HTML snapshot as a read-only preview.
- Download the original HTML snapshot.
- Download a PDF generated from that snapshot.

The PDF is generated by the server. The browser used by the visitor does not matter; users may access CSMS through Chrome, Edge, Firefox, Safari, or another browser.

## Files Used (Source of Truth)

- Snapshot and preview services
  - `app/Services/Syllabus/Snapshots/SyllabusSnapshotService.php` — creates and reads immutable HTML snapshots
  - `app/Services/Syllabus/Snapshots/SyllabusPdfService.php` — converts self-contained HTML into PDF through headless Chrome/Chromium
  - `app/Services/Syllabus/Snapshots/SyllabusPreviewService.php` — builds the data used by the syllabus preview templates
- Controller
  - `app/Http/Controllers/Syllabus/SyllabusController.php` — live previews, saved previews, HTML downloads, and PDF downloads
- Routes
  - `routes/web.php` — live and saved preview/download endpoints
- Preview templates
  - `resources/views/Syllabus/preview/complete.blade.php`
  - `resources/views/Syllabus/preview/abridged.blade.php`
  - `resources/views/Syllabus/preview/assessment.blade.php`
  - `resources/views/Syllabus/preview/_versions_drawer.blade.php`
  - `resources/views/Syllabus/preview/_transmutation_table.blade.php`
- Wizard interface
  - `resources/views/livewire/syllabus/wizard/steps/partials/review/saved-versions.blade.php`
- Model and configuration
  - `app/Models/CompleteSyllabus.php`
  - `config/filesystems.php`
  - `config/syllabus_pdf.php`

## Snapshot Creation Flow

Snapshot creation is handled by `SyllabusSnapshotService::saveVersion()`.

```text
Faculty creates a saved version
            |
            v
Render Complete, Abridged, Assessment, and Review Form HTML
            |
            v
Reserve the next version number in a database transaction
            |
            v
Write self-contained .html files to the local snapshot disk
            |
            +----> Best-effort mirror to Google Drive
            |
            v
Create the complete_syllabi database record
            |
            v
Set syllabus status to under_review
```

The snapshot contains inline preview CSS and an inline base64 logo. This makes the HTML self-contained and allows it to render without Vite or public asset URLs.

PDF files are not required during snapshot creation. They are generated only when a PDF is first requested.

## Snapshot Directory Structure

The local filesystem disk is named `syllabus_snapshots` and points to:

```text
storage/app/private/syllabus-snapshots
```

Each version uses this logical structure:

```text
Syllabus Snapshots/
└── {College}/
    └── {Department}/
        └── {Program}/
            └── {Faculty}/
                └── {Course Code}/
                    └── v{Version} ({Academic Year} {Semester})/
                        ├── Complete - {Course Code}.html
                        ├── Abridged - {Course Code}.html
                        ├── Assessment - {Course Code}.html
                        └── ReviewForm - {Course Code}.html
```

After a PDF download is requested, the corresponding PDF is cached beside the HTML:

```text
Complete - {Course Code}.pdf
Abridged - {Course Code}.pdf
Assessment - {Course Code}.pdf
```

The local snapshot disk is the source of truth. Google Drive mirroring is secondary and failure to mirror does not block local snapshot creation or PDF delivery.

## Database Record

Each saved version is represented by `complete_syllabi`.

| Column | Actual content |
|---|---|
| `pdf_path` | Complete HTML snapshot path (historical column name) |
| `abridged_path` | Abridged HTML snapshot path |
| `evaluation_path` | Assessment HTML snapshot path |
| `review_form_path` | Review form HTML snapshot path |
| `checksum` | SHA-256 checksum of Complete HTML |
| `checksum_abridged` | SHA-256 checksum of Abridged HTML |
| `checksum_evaluation` | SHA-256 checksum of Assessment HTML |
| `checksum_review_form` | SHA-256 checksum of Review Form HTML |
| `version` | Immutable version number for the syllabus |

Important: `pdf_path` currently stores the Complete HTML path despite its name. Renaming it requires a database migration and coordinated model/service changes.

## Saved Preview Flow

Saved previews continue to use HTML because the preview drawer and browser-based navigation are interactive.

```text
User opens saved preview
        |
        v
Controller authorizes access to the syllabus
        |
        v
Read saved HTML from local disk
        |
        +----> If missing locally, try Google Drive
        |
        v
Inject the saved-versions drawer before </body>
        |
        v
Return Content-Type: text/html
```

The injected drawer is for viewing and navigation only. It is hidden by print CSS and is not included visually in generated PDFs.

## HTML Download Flow

The HTML icon downloads the exact immutable snapshot stored at version-creation time.

```text
User clicks HTML icon
        |
        v
Authorize syllabus access
        |
        v
Read the selected saved .html file
        |
        v
Return text/html as an attachment
```

No conversion, Chrome process, or PDF cache is involved.

### HTML Download Routes

| Variant | Route name |
|---|---|
| Complete | `syllabus.saved.complete.html.download` |
| Abridged | `syllabus.saved.abridged.html.download` |
| Assessment | `syllabus.saved.assessment.html.download` |

## PDF Download Flow

The PDF icon uses the same frozen HTML snapshot, not current live syllabus data.

```text
User clicks PDF icon
        |
        v
Authorize syllabus access
        |
        v
Derive .pdf path from the saved .html path
        |
        +----> Cached PDF exists: return it immediately
        |
        v
Read saved HTML from local disk or Google Drive
        |
        v
Create a private temporary render directory
        |
        v
Launch installed Chrome/Chromium/Edge in headless mode
        |
        v
Chrome executes the preview pagination JavaScript
        |
        v
Chrome applies print CSS and writes a temporary PDF
        |
        v
Validate that the output begins with %PDF-
        |
        v
Cache PDF beside the HTML snapshot
        |
        +----> Best-effort mirror PDF to Google Drive
        |
        v
Return application/pdf as an attachment
        |
        v
Delete the temporary HTML, PDF, and Chrome profile
```

### PDF Download Routes

| Variant | Saved PDF route name | Live PDF route name |
|---|---|---|
| Complete | `syllabus.saved.complete.download` | `syllabus.preview.complete.download` |
| Abridged | `syllabus.saved.abridged.download` | `syllabus.preview.abridged.download` |
| Assessment | `syllabus.saved.assessment.download` | `syllabus.preview.assessment.download` |

Saved PDF downloads are cached. Live PDF downloads represent current data and are generated on every request.

## Why Chrome/Chromium Is Used

The preview templates initially contain hidden source content. Their JavaScript measures the rendered content, creates A4 pages, splits long tables, repeats table headers, and switches between portrait and landscape sections.

Dompdf is installed in the project, but it does not execute this JavaScript and has limited support for some browser layout features. Passing the existing preview HTML directly to Dompdf could produce blank, incomplete, or differently paginated documents.

Headless Chromium uses the same rendering engine as the browser preview, so the generated PDF more closely matches what users see and print manually.

## Browser Requirements

The visitor does not need Chrome. A compatible browser must be installed on the production server where Laravel/PHP runs.

Supported server-side executables:

- Google Chrome
- Chromium
- Microsoft Edge (Chromium-based)

Not supported by the current service:

- Safari
- Firefox
- Internet Explorer

No API key, username, password, OAuth token, or other credential is required.

## Automatic Executable Detection

If `SYLLABUS_PDF_CHROME_PATH` is empty, `SyllabusPdfService` checks common paths.

Windows:

```text
C:\Program Files\Google\Chrome\Application\chrome.exe
C:\Program Files (x86)\Google\Chrome\Application\chrome.exe
C:\Program Files\Microsoft\Edge\Application\msedge.exe
C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe
```

Linux:

```text
/usr/bin/google-chrome
/usr/bin/google-chrome-stable
/usr/bin/chromium
/usr/bin/chromium-browser
```

macOS:

```text
/Applications/Google Chrome.app/Contents/MacOS/Google Chrome
```

## Environment Configuration

All settings are optional when Chrome is automatically detected:

```env
SYLLABUS_PDF_CHROME_PATH=
SYLLABUS_PDF_TIMEOUT=60
SYLLABUS_PDF_VIRTUAL_TIME_BUDGET=5000
SYLLABUS_PDF_NO_SANDBOX=false
```

### Setting Reference

| Setting | Default | Purpose |
|---|---:|---|
| `SYLLABUS_PDF_CHROME_PATH` | Auto-detect | Exact Chrome/Chromium/Edge executable path |
| `SYLLABUS_PDF_TIMEOUT` | `60` | Maximum seconds allowed for one render |
| `SYLLABUS_PDF_VIRTUAL_TIME_BUDGET` | `5000` | Milliseconds Chrome gives page JavaScript before printing |
| `SYLLABUS_PDF_NO_SANDBOX` | `false` | Disables the Chrome sandbox when required by a Linux deployment |

On Windows, the service automatically uses Chrome's `--no-sandbox` mode because the sandbox may fail when PHP runs under a service account. Each render still uses a separate one-use Chrome profile.

On Linux, keep `SYLLABUS_PDF_NO_SANDBOX=false` unless Chrome fails specifically because PHP is running as root or because the host cannot initialize the sandbox. Disabling the sandbox reduces process isolation.

After changing production `.env`, clear cached configuration:

```bash
php artisan config:clear
```

## Production Deployment Checklist

1. Confirm Chrome, Chromium, or Edge is installed on the server.
2. Confirm the PHP/web-server user can execute the browser binary.
3. Set `SYLLABUS_PDF_CHROME_PATH` if the executable is outside an automatically detected path.
4. Confirm PHP can write under `storage/app/private/pdf-render`.
5. Confirm PHP can write under `storage/app/private/syllabus-snapshots`.
6. Keep `SYLLABUS_PDF_NO_SANDBOX=false` unless the host requires otherwise.
7. Run `php artisan config:clear` after changing `.env`.
8. Download one Complete, Abridged, and Assessment PDF using realistic long content.
9. Verify page orientation, table splitting, page numbers, logo, and typography.
10. Verify that a second saved PDF download uses the cached file.

## Security and Authorization

- All preview and download routes are inside authenticated middleware.
- `SyllabusController::authorizeSyllabusAccess()` checks access to the selected syllabus.
- Snapshot paths are obtained from database records rather than arbitrary request paths.
- Temporary files are created below `storage/app/private/pdf-render` using unpredictable directory names.
- Each render receives an isolated temporary Chrome profile.
- Temporary files and the Chrome profile are deleted after success or failure.
- Saved files remain on the private disk and are delivered through authorized controller responses.

## Error Conditions

### Chrome or Chromium Is Not Installed

Expected error:

```text
Chrome or Chromium is required. Configure SYLLABUS_PDF_CHROME_PATH.
```

Install a compatible browser on the server or configure the correct executable path.

### Missing Headless User Data Directory

The service supplies a unique `--user-data-dir` automatically. If this error appears, confirm PHP can create and write the temporary render directory.

### Linux Sandbox Error

First verify that the executable and its system dependencies are installed correctly. If the server intentionally runs Chrome as root and the sandbox cannot initialize, set:

```env
SYLLABUS_PDF_NO_SANDBOX=true
```

Then run `php artisan config:clear`.

### PDF Rendering Times Out

Increase the timeout carefully:

```env
SYLLABUS_PDF_TIMEOUT=120
```

For very long documents whose pagination JavaScript needs more time:

```env
SYLLABUS_PDF_VIRTUAL_TIME_BUDGET=10000
```

### HTML Download Works but PDF Fails

This normally means snapshot storage is healthy but the server-side browser cannot start. Check:

- Browser installation and executable path
- PHP process execution permissions
- Temporary directory write permissions
- Chrome sandbox errors
- Server memory and timeout limits

### An Old Saved PDF Does Not Reflect New Template Changes

Saved versions are intentionally immutable, and saved PDFs are cached. A template change should not silently change a previously frozen version. Create a new syllabus version to capture the updated template and data.

If a cached PDF is known to be corrupt, remove only that version's `.pdf` file. Its immutable `.html` source remains available and the PDF will be regenerated on the next authorized download.

## Important Maintenance Rules

- Keep HTML snapshot generation separate from PDF conversion.
- Do not replace the saved HTML snapshot when generating a PDF.
- Do not generate a saved PDF from current live syllabus data.
- Do not remove authorization checks from preview or download actions.
- Keep preview CSS and required images self-contained in snapshots.
- When changing preview pagination JavaScript, test both browser preview and PDF output.
- Use the shared `_transmutation_table.blade.php` partial in Complete, Abridged, and Assessment to prevent grading-table differences.
- Treat `pdf_path` as an HTML path until a dedicated migration formally renames or replaces it.

## Summary

CSMS stores HTML as the immutable snapshot format. HTML downloads return that source directly. PDF downloads use a server-installed Chromium browser to execute the existing pagination logic, apply print styling, and produce a PDF. Saved PDFs are cached beside their HTML sources, while live PDFs are generated from current data on every request. No external PDF API or credentials are required.

## Dompdf blank-PDF fix

The Dompdf adapter removes XML processing instructions after libxml parses the UTF-8 HTML. Passing the encoding instruction through to Dompdf caused blank output.

Saved Dompdf downloads now use `.dompdf-v2.pdf`, bypassing old `.dompdf.pdf` files automatically. Deploy both the adapter and controller changes. Existing HTML snapshots remain unchanged; old cached PDFs need not be deleted. Laravel cache clearing alone does not invalidate these files.

Run `php tests/dompdf-smoke.php --snapshots` to render the largest locally available Complete, Abridged, and Assessment snapshots into `storage/app/private/dompdf-qa`. The test checks PDF text drawing commands, not merely the PDF signature. This check detects the original empty output but does not prove content completeness or correct layout. Inspect the resulting PDFs for missing content, clipping, page breaks, and table readability before considering the Dompdf trial visually verified. Complete still uses landscape throughout.
